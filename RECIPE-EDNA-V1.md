# RECIPE — Edna Media Concierge v1 (opencode + DS4)

**Purpose:** step-by-step agentic build plan for the v1 in `PRD.md`, sized for
**opencode** driving **DS4** (local DeepSeek V4 Flash on Goliath). DS4 is fast and
cheap but not frontier: steps are deliberately atomic, each with a hard verification
gate. Run **one step per opencode session**, review the diff, commit, then start the
next step fresh. Do not let the agent chain steps.

## Session preamble (paste into every opencode session)

```
Context: repo D:\Dev\repos\ednaficator on Windows. Read PRD.md and STATUS.md first.
Rules:
- Python 3.13 via uv only: `uv run ...`, `uv add ...`. Never bare pip/python.
- Windows paths with backslashes. PowerShell cmdlets, NEVER `&&` chaining.
- No stubs presented as done. No mock objects in integration tests — Plex runs
  live on localhost:32400, test against it.
- If a verification command fails, STOP and report. Do not "fix" by weakening the test.
- Touch only files named in the current step.
```

## Step 3 — Tool-calling loop (agent)

**Do:** new `ednaficator/agent.py`: OpenAI-compatible client (LM Studio :1234 /
Ollama :11434 per env), system prompt in German defining the concierge persona and the
three tools (`resolve_and_play`, `browse`, `play_music`) mapped onto `plex_tools`.
Rules encoded in prompt: answer in the user's language; if >1 plausible match, return a
`choices` payload (machine-readable list) instead of guessing; NEVER claim playback
succeeded — success text is generated by code from `PlayResult`, not by the model.
Add CLI harness `uv run python -m ednaficator.agent "spiel kommissar rex"`.
**Verify:** CLI harness: (a) unambiguous query → `play()` called with correct
ratingKey (log line proves it), (b) ambiguous query ("miss marple") → choices list,
(c) nonsense query → polite German no-match. All three demonstrated in output.
**Commit:** `feat: local-LLM tool-calling agent loop with CLI harness`

## Step 4 — Telegram bot (agent)

**Do:** `uv add python-telegram-bot`. New `ednaficator/bot.py`: long-polling (no
webhook/tunnel needed), hard allowlist from `EDNA_ALLOWED_IDS` (silently ignore
others), text messages → agent loop, `choices` payload → InlineKeyboard buttons →
callback plays selection. Per-user JSON config `users.json` (git-ignored):
telegram_id → {name, plex_client}. Entry point: `uv run python -m ednaficator.bot`.
**Verify:** Sandra sends "spiel kommissar rex" from her own Telegram → playback starts
on `EDNA_DEFAULT_CLIENT`; a non-allowlisted account gets no response. Screenshot/log.
**Commit:** `feat: telegram bot front-end with allowlist and choice buttons`

## Step 5 — Voice notes (agent)

**Do:** `uv add faster-whisper`. In `bot.py`: voice message → download .ogg →
faster-whisper (`large-v3-turbo`, device=cuda, compute_type=int8, language=de
default) → transcribed text into the same agent path; echo transcript back to the
user ("Verstanden: …") so mishears are visible.
**Verify:** Austrian-German voice note "spü mir an Ambros" → transcript echoed →
music starts. Log the end-to-end latency; flag if transcription alone exceeds ~2 s.
**Commit:** `feat: voice-note input via faster-whisper`

## Step 10 — `photo_slideshow` tool (agent)

**Do:** add tool to `agent.py`: LLM decomposes the request into

months: list[int] | None}` → Immich search (person ∩ smart-search ∩ date) → top 40 →

what WAS found ("Vom Onkel Franz hab ich nur Sommerfotos — soll ich die zeigen?").
**Verify:** "hochzeitsfotos" → slideshow plays; "mitm onkel franz im winter" →
slideshow whose first photos visibly contain the labeled person; logs show the
decomposed query.
**Commit:** `feat: photo_slideshow tool (immich search -> ffmpeg -> plex)`
